## The Print Controller (Chimera)

Chimera is a Qt desktop application running on a Windows machine on the local network. It controls an industrial inkjet printhead.

### How it works
Chimera reads two files from its `scripts/` folder:
- A `.ykr` **template file** — JSON describing the label layout (designed once in the Chimera editor, not generated by vdampro)
- A `.txt` **variable data file** — one line per label, columns delimited by a configurable separator (default: comma)

The template is pre-designed to have these columns in order:
- Column 0 → QR code content
- Column 1 → Company / customer name
- Column 2 → Asset tag
- Column 3 → Asset name
- Column 4 → Serial number

Example `.txt` file content (one line = one label to print):
```
https://assets.example.com/hardware/AHK-0001,Acme Corp,AHK-0001,Dell Latitude 5520,SN-ABC123
https://assets.example.com/hardware/AHK-0002,Acme Corp,AHK-0002,HP EliteBook 840,SN-DEF456
```

### TCP interface
Chimera runs a TCP server on port **1680** at a configurable IP address. The current IP in the Chimera config is `192.168.109.1` but this changes when networks change, which is why the IP must be configurable from vdampro's settings UI.

The TCP protocol is to be treated as **raw line delivery** — each label record is a newline-terminated string sent over the socket. If this proves incorrect during implementation, fall back to writing the `.txt` file to a configurable shared path instead. Build the delivery mechanism as a swappable strategy so either method can be used.

### 4. ChimeraPrintService

**New file:** `app/Services/ChimeraPrintService.php`

This service handles formatting and delivering variable data to the Chimera printer. It should be a plain PHP class (not a Laravel facade) that can be called from controllers.

```php
class ChimeraPrintService
{
    public function __construct(private Setting $settings) {}

    /**
     * Send a collection of assets to the Chimera print controller.
     * Returns ['success' => bool, 'message' => string, 'count' => int]
     */
    public function printAssets(Collection $assets): array

    /**
     * Format a single asset as a comma-separated variable data line.
     * Column order: qr_content, company, asset_tag, asset_name, serial
     */
    public function formatLine(Asset $asset): string

    /**
     * Build the QR code content for an asset.
     * Uses chimera_qr_prefix setting + asset tag.
     * If prefix is a full URL base, appends the asset tag.
     * If prefix is empty, uses asset tag alone.
     */
    private function buildQrContent(Asset $asset): string

    /**
     * Deliver formatted lines via TCP socket to chimera_printer_ip:chimera_printer_port.
     * Opens connection, sends all lines, closes connection.
     */
    private function deliverViaTcp(array $lines): array

    /**
     * Deliver formatted lines by writing a .txt file to chimera_scripts_path.
     * Filename: chimera_print_YYYYMMDD_HHmmss.txt
     */
    private function deliverViaFile(array $lines): array
}
```

The `formatLine()` method must:
- Wrap each field in quotes if it contains a comma
- Use the company name from the asset's company relationship (if set), otherwise empty string
- Use asset serial number (if set), otherwise empty string
- Escape any newline characters within field values

## Key Constraints and Patterns to Follow

- **Settings storage:** All settings are stored as a single row in the `settings` table, accessed via `Setting::getSettings()`. There is never more than one row. Follow `postLabels()` exactly for how to save settings fields.
- **No new packages:** Use only what's already in the project. PHP's native `fsockopen()` or `stream_socket_client()` is sufficient for TCP. No Guzzle needed.
- **Authorization:** Wrap all new settings routes with the same admin middleware that wraps `admin/labels`. Check how `admin/labels` is guarded in `routes/web.php` and replicate.
- **Validation:** Add a `StoreChimeraPrinterSettings` Form Request class in `app/Http/Requests/` following the pattern of the existing `StoreLabelSettings` request. Validate that IP is a valid IP address when `chimera_delivery_method` is `tcp`.
- **Error handling:** If the TCP connection fails (timeout, refused), catch the error and return a user-friendly message. Do not throw unhandled exceptions. Set a 3-second socket timeout.
- **No changes to `.ykr` template files.** Those are managed entirely in the Chimera editor by the operator. vdampro only generates and delivers the `.txt` variable data.

## Context: What the .ykr Template Looks Like

The Chimera label template (`.ykr`) is a JSON file that defines the physical label. It is pre-configured by the operator and **not generated by vdampro**. A typical label for this use case has:

```json
{
    "canvas": {
        "height": 25.4,
        "width": 100,
        "penheight": 12.7
    },
    "items": [
        {
            "type": "barcode",
            "barcode_type": "BARCODE_QRCODE",
            "string": [{ "type": "text", "params": { "text": "placeholder" } }]
        },
        {
            "type": "text",
            "string": [{ "type": "text", "params": { "text": "placeholder" } }]
        }
    ],
    "runningenvironment": {
        "variableContext": {
            "SourceType": 1,
            "SplitChar": ",",
            "SplitColumnCount": 5,
            "SplitRowCount": 1
        }
    }
}
```

The `SplitChar` delimiter must match what vdampro uses in `formatLine()`. Default is comma. If the operator changes it in Chimera, the `chimera_qr_prefix` field in vdampro settings can be used to adjust, but the delimiter itself should also be a configurable setting if possible.
